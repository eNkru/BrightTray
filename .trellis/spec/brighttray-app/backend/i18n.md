# i18n

The app speaks Chinese and English. Chinese is the primary language of the
project; English is the fallback.

## Rust side: `tr(zh, en)`

```rust
/// Picks the Chinese or English text for the current language.
pub fn tr(zh: &'static str, en: &'static str) -> &'static str {
    match lang() {
        Lang::Zh => zh,
        Lang::En => en,
    }
}
```

**Chinese always comes first.** Both arguments are `&'static str`, so the
strings live in the binary and the call site reads as a pair.

```rust
self.error = Some(
    tr(
        "这台显示器已断开，请刷新后重试。",
        "This display is no longer connected. Refresh and try again.",
    )
    .into(),
);
```

Every user-visible string goes through `tr()`. The only untranslated string in
the app is the product name `BrightTray` (window title, tray tooltip). The
tray menu items are translated the same way:

```rust
let show_item = MenuItem::new(tr("打开 BrightTray", "Open BrightTray"), true, None);
let restart_item = MenuItem::new(
    tr(
        "重启 ShellHost（开始菜单会短暂消失）",
        "Restart ShellHost (the Start menu disappears briefly)",
    ),
    true,
    None,
);
let quit_item = MenuItem::new(tr("退出", "Quit"), true, None);
```

A tray item that ends a shell process puts the consequence in its own label,
because the tray menu has no confirmation dialog.

## Language detection

`i18n::lang()` is cached in a `OnceLock`, so it is detected once per process.

1. `BRIGHTTRAY_LANG=zh|en` forces the language (`BRIGHTTRAY_LANG=zh-CN` also
   works — the check is `starts_with`).
2. Otherwise the Windows UI language decides:

   ```rust
   // LANG_CHINESE is primary language 0x04 for every Chinese locale.
   const LANG_CHINESE: u16 = 0x04;
   let id = unsafe { windows::Win32::Globalization::GetUserDefaultUILanguage() };
   if id & 0x3ff == LANG_CHINESE { Lang::Zh } else { Lang::En }
   ```

Any Chinese locale maps to Chinese; everything else to English.

## Page side: the `STRINGS` table

`app/ui/index.html` has its own table, because the page cannot call into Rust:

```javascript
const STRINGS = {
  zh: { displays: "显示器", autostart: "开机自启动", apply: "应用", ... },
  en: { displays: "Displays", autostart: "Start with Windows", apply: "Apply", ... },
};
const T = STRINGS[document.documentElement.lang] || STRINGS.en;
```

The `<html lang>` attribute comes from the `{{LANG}}` placeholder, which Rust
substitutes with `i18n::lang().code()` — `zh` or `en`.

Elements are filled by their `data-t` / `data-title` attribute:

```html
<h2 data-t="displays"></h2>
<button class="icon-btn" id="btn-refresh" data-title="refresh">
```

**Adding a page string means adding it to both `zh` and `en`.** A key that
exists in only one map renders as `undefined` in the other language.

## The two sides must stay in sync

| Where | What |
|-------|------|
| `app/src/i18n.rs` | Rust-side strings, through `tr()` |
| `app/ui/index.html` | page strings, in `STRINGS` |
| `app/src/main.rs` | the `push_state()` `hook.kind` mapping |

The page's status text for each `hook.kind` is in the page's `STRINGS`
(`idle`, `running`, `waiting`, `hooking`, `missing`,
`starting`) — those keys have no `data-t` attribute, they are looked up by
name in `statusOf()`.
